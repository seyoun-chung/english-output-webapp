# 문제·오류 기록

사용자 테스트에서 확인된 문제를 **관찰 사실 → 해결 액션 아이템 → 검증 결과** 순서로 기록한다. 원인 추정은 확인된 사실과 구분한다. 새 문제가 나오면 해결 여부와 관계없이 여기에 추가하고, 기존 항목도 상태가 바뀌면 갱신한다. 개인 IP, 녹음 파일, 인증서·키는 기록하지 않는다.

상태: `해결 확인`은 실제 사용 환경에서 재시험을 통과한 경우, `수정됨·추가 검증 필요`는 일부 환경에서만 확인한 경우, `열림`은 조치 또는 사용자 결정이 남은 경우다. 코드의 배포 여부는 해당 PR의 병합 상태와 별도로 확인한다.

## 2026-09-30 · 휴대폰의 일반 HTTP 접속에서 녹음 불가

- **문제 정의:** 같은 Wi-Fi에서 컴퓨터의 사설 IP를 일반 HTTP로 열면 학습 화면은 보이지만 휴대폰에서 마이크 녹음이 작동하지 않았다.
- **확인된 원인:** 모바일 브라우저의 마이크 API는 보안 컨텍스트가 필요하다. 컴퓨터의 사설 IP를 쓰는 일반 HTTP는 `localhost` 예외에 해당하지 않는다.
- **액션 아이템:** 휴대폰 시험용 HTTPS 서버를 사용하고, 휴대폰에서 주소 표시줄의 HTTPS 연결 및 마이크 권한을 확인한다.
- **해결 여부:** `해결 확인` — HTTPS 접속 후 녹음 파일 생성까지 확인했다. 다만 이 조치만으로 재생 무음 문제는 해결되지 않아 아래 항목으로 분리했다.

## 2026-09-30 · iPhone에서 로컬 HTTPS 접속 경고

- **문제 정의:** 휴대폰에서 개발 서버 주소를 열었을 때 Safari가 비공개 연결 경고를 표시해 앱에 접속할 수 없었다.
- **확인된 원인:** 로컬 개발용 CA가 휴대폰에서 아직 신뢰되지 않았다. 공개 인증서가 아닌 로컬 인증서를 사용하는 테스트 환경이다.
- **액션 아이템:** 공개 키 인증서(`local-ca.cer`)만 휴대폰에 설치하고, 해당 개발용 CA의 전체 신뢰를 켠 뒤 HTTPS 주소를 다시 열기. 개인 키는 휴대폰으로 옮기지 않는다.
- **해결 여부:** `해결 확인` — 사용자가 HTTPS 앱 접속을 확인했다. 테스트가 끝나면 휴대폰의 개발용 인증서 프로파일을 제거하거나 신뢰를 해제한다. 제거 후 같은 로컬 HTTPS 서버를 다시 시험하려면 인증서를 재설치·신뢰해야 한다.

## 2026-09-30 · iPhone 녹음은 만들어지지만 재생 소리가 나지 않음

- **문제 정의:** 녹음 시작·종료 후 짧은 파일이 만들어지고 재생 막대도 움직였으나, 휴대폰에서 소리가 들리지 않았다. 마이크를 바꾸어 재시험해도 같았다.
- **원인 분석:** iPhone에서도 WebM을 먼저 선택하던 형식 우선순위가 재생 호환성에 영향을 주었을 가능성이 있다. 브라우저 내부의 정확한 실패 원인은 확인되지 않았으므로 단정하지 않는다.
- **액션 아이템:** iPhone/iPad에서 지원하면 MP4를 우선 선택하고, 지원하지 않을 때만 WebM으로 대체한다. 다른 환경의 기존 WebM 우선순위는 유지한다. 형식 선택 회귀 테스트와 전체 검증을 실행하고 실제 iPhone에서 다시 녹음·재생한다.
- **해결 여부:** `해결 확인` — 자동 테스트·빌드가 통과했고, 사용자가 iPhone 재생 소리가 정상적으로 난다고 확인했다. 구현 브랜치는 `codex/fix-ios-recording`이다.

## 2026-09-30 · Chapter 3 완료 후 Finish 버튼이 다시 보이지 않음

- **문제 정의:** 필수 영역 4/4를 마친 뒤 `Finish chapter`가 한 번 표시되지만, 완료 처리와 Chapter Review 재방문 후에는 보이지 않아 다음 단계가 불명확하다. 다음 챕터로 가는 버튼도 없다.
- **확인된 동작:** 완료 시점은 `pass1CompletedAt`으로 저장되고 완료 화면은 `Chapter complete`를 표시한다. 완료 후 버튼은 Chapter Review로 바뀐다. Chapter 4는 현재 시범 구현 범위에 없다. 필수 학습 기록이 사라졌다는 증거는 없다.
- **액션 아이템:** Home에서 필수 4/4 직후 `Finish chapter`를 제공한다. 완료 후에는 `Chapter 3 complete` 상태를 Home과 Chapter progress에 유지하고, Chapter 4는 이 시범판에서 아직 제공되지 않음을 알린다. 실제 Chapter 4 이동은 구현 범위 결정 전까지 추가하지 않는다.
- **해결 여부:** `수정됨·추가 검증 필요` — 자동 테스트 247개·빌드가 통과했다. Aside의 새 테스트 탭에서 실제 버튼으로 필수 4영역을 완료하고 `Finish chapter → Chapter Review → Home`을 이동했을 때 완료 표시가 유지되는 것을 PC 레이아웃에서 확인했다. 좁은 모바일 너비의 일반 화면은 확인했지만, **완료 상태의 모바일 실기기 레이아웃은 아직 재확인하지 않았다.** 구현 브랜치는 `codex/fix-ios-recording`이다.

## 새 문제 기록 양식

```text
날짜 · 화면/기기 · 상태(열림/수정됨·추가 검증 필요/해결 확인)
문제 정의: 기대한 동작, 실제 동작, 재현 순서
증거와 원인: 확인된 사실과 가설을 분리
액션 아이템: 담당할 수정/검증, 필요한 사용자 결정
해결 여부: 자동 검증 결과, 실제 기기 재시험 결과, 관련 PR
```
