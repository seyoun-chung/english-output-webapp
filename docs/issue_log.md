## 2026-10-04 · 서버 자동저장 복구 사본 무제한 누적

- 확인: 성공한 sync마다 전체 progress를 history에 추가하고 보관 개수 제한이 없었다.
- 영향: 사용자 수뿐 아니라 자동 저장 횟수에 따라 DB 저장량이 증가한다. 200명 무료 운영을 보장할 수 없다.
- 사용자 위임에 따른 로컬 조치: 최근 3개 저장 + 최근 저장일 7일의 첫 사본, 중복 제외 최대 10개.
  현재 기록/브라우저 사본/다운로드 백업 보존. 한 사용자 저장과 정리를 동일 transaction으로 처리한다.
- 테스트: 가짜 자료 10일×100회 저장, 하루 첫 사본/최근 사본 보존, 타 사용자 격리,
  설치 시 기존 이력 무삭제, rollback, 최신 작문/재시도/충돌/RLS 보호 확인.
- 실제 서비스 미적용: 운영 데이터 삭제/부하/용량 검증은 미실행. 전체 사용량/큰 기록 크기에 따른 제한은 남는다.
- 후속 UTC 경계 테스트의 SQL fixture에서 같은 파라미터를 bigint/int로 혼용해 첫 실행이 실패했다.
  fixture를 bigint로 통일했다. 제품 migration 오류와 구분하며 최종 재검증 결과는 verification 참조.

## 2026-10-01 · 내장 브라우저의 마이크 권한 요청이 끝나지 않음

- **문제 정의:** Windows에서 마이크 사용을 허용했지만 Codex 내장 브라우저에서 `Record`를 누르면 `Waiting for permission…` 상태가 끝나지 않았다.
- **확인된 사실과 원인:** Windows 마이크 개인정보 설정은 `Allow`이고 Internal/External Microphone 장치는 모두 `OK`였다. localhost는 보안 컨텍스트이고 녹음 API도 존재했다. 기존 내장 브라우저 탭에서는 `getUserMedia` 요청이 허용·거부 어느 쪽으로도 완료되지 않았지만, 새 내장 브라우저 탭에서는 같은 앱과 진행 상태로 권한 요청이 완료됐다. 따라서 마이크 장치나 녹음 생성 로직의 고장이 아니라 기존 탭의 권한 요청 상태가 멈춘 사례로 확인했다.
- **액션 아이템:** 응답 없는 권한 요청을 15초 후 종료하고 사이트 마이크 권한 또는 일반 Chrome/Edge 사용을 안내한다. 늦게 권한이 승인되어 스트림이 도착하더라도 즉시 트랙을 종료해 백그라운드 녹음을 방지한다.
- **해결 여부:** `해결 확인` — 새 내장 브라우저 탭에서 실제 `Record → Stop recording → Your recording 생성 → 재생`을 실행했고 재생 컨트롤이 `일시중지`로 바뀌는 것을 확인했다. 응답 없는 권한 요청의 타임아웃과 늦은 권한 승인 시 스트림 해제도 자동 테스트로 추가했다. 이후 사용자가 External Microphone의 Windows 음소거를 해제한 실제 이어폰 환경에서 입력 표시 움직임, 녹음, 목소리 재생, 녹음 삭제를 모두 확인했다.

## 2026-10-02 · 이어폰 외장 마이크의 Windows 음소거 재발

- **문제 정의:** 내장 마이크는 녹음되지만 이어폰 마이크로 녹음하면 목소리가 들리지 않았다.
- **확인된 사실:** 최초 조회에는 외장 마이크가 연결되지 않은 상태였고, 재조회에는
  External Microphone과 헤드폰이 모두 `OK`였다. Core Audio 조회에서 일반·통신 기본
  입력 모두 외장 마이크, 입력 볼륨 100%, 외장 마이크 음소거 `True`를 확인했다.
- **조치:** 사용자의 녹음 복구 요청에 따라 외장 마이크 음소거를 해제하고 `False`를 확인했다.
- **해결 여부:** `해결 확인` — 해제 후 사용자가 새 녹음의 목소리가 잘 들린다고 확인했다.
- **재발 원인:** 음소거를 다시 켠 동작·프로그램·드라이버는 아직 확인되지 않았다.
  이어폰 고장이나 특정 프로그램 문제라고 단정하지 않는다.
- **예방:** AGENTS.md에 Microphone preflight를 필수화했다. 장치 인식만 확인하지 않고
  매 녹음 검증마다 기본 입력·음소거·볼륨·브라우저 실제 입력과 새 녹음을 확인한다.
  이 절차는 조기 발견을 위한 것이며 운영체제 음소거 재발을 막는 앱 수정은 아니다.
