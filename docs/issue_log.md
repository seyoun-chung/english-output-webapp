# 문제·오류 기록

사용자 테스트에서 확인된 문제를 **관찰 사실 → 해결 액션 아이템 → 검증 결과** 순서로 기록한다. 원인 추정은 확인된 사실과 구분한다. 새 문제가 나오면 해결 여부와 관계없이 여기에 추가하고, 기존 항목도 상태가 바뀌면 갱신한다. 개인 IP, 녹음 파일, 인증서·키는 기록하지 않는다.

상태: `해결 확인`은 실제 사용 환경에서 재시험을 통과한 경우, `수정됨·추가 검증 필요`는 일부 환경에서만 확인한 경우, `열림`은 조치 또는 사용자 결정이 남은 경우다. 코드의 배포 여부는 해당 PR의 병합 상태와 별도로 확인한다.

## 2026-10-02 · What About You 질문 출처가 고정 페이지로 표시됨

- **문제 정의:** Chapter 7의 첫 `What About You?` 질문은 교재 p.152에 있지만 화면에는 `Let’s Have a Talk · p.154`로 표시됐다.
- **확인된 원인:** 공통 `QuestionPicker`가 선택된 질문의 provenance 대신 모든 질문에 `whatAboutYou + 2` 페이지와 `Let’s Have a Talk` 문구를 고정 표시했다.
- **액션 아이템:** 선택된 질문의 `section`과 `sourcePage` metadata를 표시하고, Chapter 7의 첫 질문과 두 번째 질문이 각각 p.152와 p.154를 표시하는 회귀 테스트를 추가한다.
- **해결 여부:** `해결 확인` — 관련 테스트 51개가 통과했고 내장 브라우저에서 첫 질문이 `What About You? · p.152`로 표시되는 것을 재확인했다. 전체 검증 결과는 Chapter 7 검증 기록에 포함한다.

## 2026-09-30 · 휴대폰의 일반 HTTP 접속에서 녹음 불가

- **문제 정의:** 같은 Wi-Fi에서 컴퓨터의 사설 IP를 일반 HTTP로 열면 학습 화면은 보이지만 휴대폰에서 마이크 녹음이 작동하지 않았다.
- **확인된 원인:** 모바일 브라우저의 마이크 API는 보안 컨텍스트가 필요하다. 컴퓨터의 사설 IP를 쓰는 일반 HTTP는 `localhost` 예외에 해당하지 않는다.
- **액션 아이템:** 휴대폰 시험용 HTTPS 서버를 사용하고, 휴대폰에서 주소 표시줄의 HTTPS 연결 및 마이크 권한을 확인한다.
- **해결 여부:** `해결 확인` — HTTPS 접속 후 녹음 파일 생성까지 확인했다. 다만 이 조치만으로 재생 무음 문제는 해결되지 않아 아래 항목으로 분리했다.

## 2026-09-30 · iPhone에서 로컬 HTTPS 접속 경고

- **문제 정의:** 휴대폰에서 개발 서버 주소를 열었을 때 Safari가 비공개 연결 경고를 표시해 앱에 접속할 수 없었다.
- **확인된 원인:** 로컬 개발용 CA가 휴대폰에서 아직 신뢰되지 않았다. 공개 인증서가 아닌 로컬 인증서를 사용하는 테스트 환경이다.
- **액션 아이템:** 공개 키 인증서(`local-ca.cer`)만 휴대폰에 설치하고, 해당 개발용 CA의 전체 신뢰를 켠 뒤 HTTPS 주소를 다시 열기. 개인 키는 휴대폰으로 옮기지 않는다.
- **해결 여부:** `해결 확인` — 사용자가 HTTPS 앱 접속을 확인했다. 테스트가 끝나면 휴대폰의 개발용 인증서 프로파일을 제거하거나 신뢰를 해제한다. 제거 후 같은 로컬 HTTPS 서버를 다시 시험하려면 인증서를 재설치·신뢰해야 한다.

## 2026-09-30 · iPhone 녹음은 만들어지지만 재생 소리가 나지 않음

- **문제 정의:** 녹음 시작·종료 후 짧은 파일이 만들어지고 재생 막대도 움직였으나, 휴대폰에서 소리가 들리지 않았다. 마이크를 바꾸어 재시험해도 같았다.
- **원인 분석:** iPhone에서도 WebM을 먼저 선택하던 형식 우선순위가 재생 호환성에 영향을 주었을 가능성이 있다. 브라우저 내부의 정확한 실패 원인은 확인되지 않았으므로 단정하지 않는다.
- **액션 아이템:** iPhone/iPad에서 지원하면 MP4를 우선 선택하고, 지원하지 않을 때만 WebM으로 대체한다. 다른 환경의 기존 WebM 우선순위는 유지한다. 형식 선택 회귀 테스트와 전체 검증을 실행하고 실제 iPhone에서 다시 녹음·재생한다.
- **해결 여부:** `해결 확인` — 자동 테스트·빌드가 통과했고, 사용자가 iPhone 재생 소리가 정상적으로 난다고 확인했다. 구현 브랜치는 `codex/fix-ios-recording`이다.

- **해결 여부:** `수정됨·추가 검증 필요` — 자동 테스트 247개·빌드가 통과했다. Aside의 새 테스트 탭에서 실제 버튼으로 필수 4영역을 완료하고 `Finish chapter → Chapter Review → Home`을 이동했을 때 완료 표시가 유지되는 것을 PC 레이아웃에서 확인했다. 좁은 모바일 너비의 일반 화면은 확인했지만, **완료 상태의 모바일 실기기 레이아웃은 아직 재확인하지 않았다.** 구현 브랜치는 `codex/fix-ios-recording`이다.

## 2026-10-01 · 내장 브라우저의 마이크 권한 요청이 끝나지 않음

- **문제 정의:** Windows에서 마이크 사용을 허용했지만 Codex 내장 브라우저에서 `Record`를 누르면 `Waiting for permission…` 상태가 끝나지 않았다.
- **확인된 사실과 원인:** Windows 마이크 개인정보 설정은 `Allow`이고 Internal/External Microphone 장치는 모두 `OK`였다. localhost는 보안 컨텍스트이고 녹음 API도 존재했다. 기존 내장 브라우저 탭에서는 `getUserMedia` 요청이 허용·거부 어느 쪽으로도 완료되지 않았지만, 새 내장 브라우저 탭에서는 같은 앱과 진행 상태로 권한 요청이 완료됐다. 따라서 마이크 장치나 녹음 생성 로직의 고장이 아니라 기존 탭의 권한 요청 상태가 멈춘 사례로 확인했다.
- **액션 아이템:** 응답 없는 권한 요청을 15초 후 종료하고 사이트 마이크 권한 또는 일반 Chrome/Edge 사용을 안내한다. 늦게 권한이 승인되어 스트림이 도착하더라도 즉시 트랙을 종료해 백그라운드 녹음을 방지한다.
- **해결 여부:** `해결 확인` — 새 내장 브라우저 탭에서 실제 `Record → Stop recording → Your recording 생성 → 재생`을 실행했고 재생 컨트롤이 `일시중지`로 바뀌는 것을 확인했다. 응답 없는 권한 요청의 타임아웃과 늦은 권한 승인 시 스트림 해제도 자동 테스트로 추가했다. 이후 사용자가 External Microphone의 Windows 음소거를 해제한 실제 이어폰 환경에서 입력 표시 움직임, 녹음, 목소리 재생, 녹음 삭제를 모두 확인했다.

## 2026-10-02 · 이어폰 외장 마이크의 Windows 음소거 재발

- **문제 정의:** 내장 마이크는 녹음되지만 이어폰 마이크로 녹음하면 목소리가 들리지 않았다.
- **확인된 사실:** 최초 조회에는 외장 마이크가 연결되지 않은 상태였고, 재조회에는
  External Microphone과 헤드폰이 모두 `OK`였다. Core Audio 조회에서 일반·통신 기본
  입력 모두 외장 마이크, 입력 볼륨 100%, 외장 마이크 음소거 `True`를 확인했다.
- **조치:** 사용자의 녹음 복구 요청에 따라 외장 마이크 음소거를 해제하고 `False`를 확인했다.
- **해결 여부:** `해결 확인` — 해제 후 사용자가 새 녹음의 목소리가 잘 들린다고 확인했다.
- **재발 원인:** 음소거를 다시 켠 동작·프로그램·드라이버는 아직 확인되지 않았다.
  이어폰 고장이나 특정 프로그램 문제라고 단정하지 않는다.
- **예방:** AGENTS.md에 Microphone preflight를 필수화했다. 장치 인식만 확인하지 않고
  매 녹음 검증마다 기본 입력·음소거·볼륨·브라우저 실제 입력과 새 녹음을 확인한다.
  이 절차는 조기 발견을 위한 것이며 운영체제 음소거 재발을 막는 앱 수정은 아니다.
